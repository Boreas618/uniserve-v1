# media

Host media of the main process: H.264/AAC output encoding and MP4 muxing,
conditional media reading, and the host resamplers model conditioning uses.
The crate is the implementation of `specs/worker.md` §3's `media/` row and §9's
media replacements; it is called by `crates/executor`'s media runner on the
main process's blocking thread pool.

## Native runtime

The codec calls go through one C shim (`src/ffi/shim.c`) over FFmpeg 8.1.2's
headers. The crate builds against a **shared** FFmpeg 8.1.2 that has libx264:
the environment's installation at `/opt/uv/ffmpeg-8.1.2` is static and was
configured without external libraries, so it has no H.264 encoder. The
runtime the crate links is provisioned by the committed script
`crates/media/native/build.sh`, which builds libx264 (pinned by SHA-256) and
then FFmpeg 8.1.2 (`--enable-shared --enable-rpath --enable-libx264
--enable-version3`) from the environment's FFmpeg source into
`artifacts/native/prefix`. `--enable-rpath` bakes the prefix's `lib` into the
runtime's own executables and shared libraries, so `bin/ffmpeg` and
`bin/ffprobe` run without `LD_LIBRARY_PATH`, and a `cargo` test process links
the same way. That directory is git-ignored; rebuild it with:

```sh
crates/media/native/build.sh            # into artifacts/native/prefix
crates/media/native/build.sh /some/prefix
```

The build script finds the runtime in `UNISERVE_FFMPEG_DIR` when set, and in
`<workspace>/artifacts/native/prefix` otherwise. Headers and shared libraries
must both be present. The static `/opt/uv/ffmpeg-8.1.2/bin/ffmpeg` and
`ffprobe` stay in use as external programs: the reference video decoder is an
external `ffmpeg` process by design, and tests validate MP4s with `ffprobe`.

## External programs

`MediaConfig::ffmpeg` names the `ffmpeg` executable used to decode reference
videos. `MediaConfig::from_env` takes it from `UNISERVE_FFMPEG`, else uses the
linked runtime's own `bin/ffmpeg`, else `ffmpeg` from the loader's search
path. Either binary must be able to decode H.264 and AAC; the runtime prefix's
own `ffmpeg` is the natural choice and needs no environment beyond its baked
rpath.

## Tests

All tests are run by the caller (`specs/WORK.md`): `cargo test -p media` from
a worktree whose `artifacts/native/prefix` exists (`UNISERVE_FFMPEG_DIR` may
point elsewhere). `UNISERVE_FFMPEG` selects the reference-video decoder and
`UNISERVE_FFPROBE` the MP4 validator, both defaulting to that prefix's `bin/`.
Reference fixtures live under `tests/fixtures/` and are regenerated by their
`generate.py` scripts against the reference implementations.

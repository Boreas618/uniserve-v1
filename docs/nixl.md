# NIXL transfers

UniServe's Transfer Server reads storage of other hosts through NIXL with the UCX backend, which it loads at run time: building UniServe needs no NIXL installation, and a host that serves no other host and reads from none never loads it. The bindings bind the C API of NIXL 1.5.1 (`crates/storage-server/src/transfer/nixl/mod.rs`, `RELEASE`).

## Provisioning

NIXL and UCX are installed as packages, so the loader's default search path finds NIXL's C API (`libnixl_capi.so`), and NIXL finds its UCX backend plugin and UCX's libraries where the packages put them: no `LD_LIBRARY_PATH`, run path rewrite, plugin directory variable or library path setting is involved. A Transfer Server whose host lacks the package fails each task that needs NIXL with an error naming the library and the release.

Reading a read-only host tensor of another host needs registrations for remote reads alone, which NIXL's UCX backend and UCX's InfiniBand memory domain support in UniServe's NIXL and UCX packages: NIXL passes the requested read access to UCX, and UCX registers the mapping without requesting write access. With packages without it, the registration of such a tensor fails, and so does the task that reads it; every other transfer works with the upstream releases.

## Behaviour

The Transfer Server's agent takes NIXL's default configuration with a progress thread, and its UCX backend states its UCX settings itself (`crates/storage-server/src/transfer/nixl/agent.rs`). It uses pinned registration and disables its registration cache (`REG_NONBLOCK_MEM_TYPES=` and `RCACHE_ENABLE=n`): a released CUDA mapping can be reused at the same virtual address, so registrations must follow the backing allocation's lifetime. It opens the host's usable RDMA ports alone (`NET_DEVICES`), since UCX fails to start when it cannot open a port it found (an Ethernet port without a usable GID fails it with `Address not valid`): the ports whose link is active and whose GID table holds an address, as the kernel states them (`/sys/class/infiniband`). A host without a usable port fails each task that needs NIXL, saying so. `storage_config.nixl_transports` selects the transports: those UCX selects by itself, or RDMA between processes and CUDA copies within one (`TLS=rc,cuda_copy`). On hosts in the same NVLink fabric, the Transfer Server uses imported CUDA fabric handles when available and RDMA otherwise.

The rate of READs into each end of the host is part of the host's transfer calibration (`uniserve storage-server calibrate --reads`, `docs/configuration.md` under `storage_config`): two agents of the calibration step READ between each other through the host's RDMA ports. A host whose calibration states no READ rate fails each task that READs from another host.

Transfers between hosts read device storage and host storage: a handoff's import read from a prefill replica on another host, and the products of a media deployment whose worker groups span two hosts. A handoff's push writes instead: the lender host's Transfer Server WRITEs each page into the decode replica's device storage, registered for remote writes by the decode host's Transfer Server (`Region::Remote` as a destination), and the WRITE is costed at the host's calibrated READ rate, the same RDMA path the other way. A Storage Server that accepts other hosts (`storage_config.tcp`) starts its Transfer Server's NIXL agent when the Transfer Server starts, so the first read from or of the host does not wait for UCX to come up; any other starts it at the first task that needs it.

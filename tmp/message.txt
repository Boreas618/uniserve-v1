feat(kernels): packages take model's operator names, descriptor fields and launch orders

The kernel programs are compiled for the descriptors `crates/ops` publishes, so
their names, their `[kernel.descriptors]` dimensions and the pack order of their
launch parameters are that crate's, not this package's invention:

- operator names follow `Op::NAME`: `kv_write`, `rotary_factors`,
  `topk_softmax`, `expert_gather`, `logits_gather`, `logits_shape`,
  `log_softmax` (with a separate `logprob_gather` package).
- descriptor dimensions are model's `Key::field` names in their declaration
  order, with model's value sets: `dtype, columns, tile, pdl` for the
  normalizations, `dtype, positions, columns, block, scale, pdl` for the rotary
  factors, `dtype, ids, hidden, first, rows, block, pdl` for the embedding,
  `scores, experts, top, renormalize, scale` for the routing.
- launch parameters follow each operator's `Arguments` pack order, with the
  values it passes at run time (row width, token count, page geometry) read as
  parameters instead of being baked in.

`topk_softmax` becomes a cubin in place of the native launcher: the descriptor
bakes the per-lane score count and the renormalizing butterfly's width, one warp
routes one token, and the module declares the four warps and zero dynamic shared
memory the operator's launch checks. Its compile script is now in the tree, which
it was not.

Validated by compiling one descriptor of each package: triton.compile on
GPUTarget(cuda, 100, 32) for the Triton ones, nvcc 13.0.48 --cubin -arch=sm_100a
for the routing one.
